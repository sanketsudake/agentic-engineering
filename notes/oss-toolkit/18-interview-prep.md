# 18 Interview Prep

> Forty questions asked in AI engineer and agent developer interviews, with the shape of a strong answer.

| Question | Level | Topic | What A Strong Answer Covers |
|---|---|---|---|
| What is the difference between a workflow and an agent | Fresher | Fundamentals | A workflow has predetermined steps in code. An agent decides its own next step at runtime using an LLM. Most production systems are workflows with a small agentic core, because determinism is cheaper and easier to debug |
| Explain the think, act, observe loop | Fresher | Fundamentals | Model reasons about the goal, selects a tool with arguments, the runtime executes it, the result is appended to context, repeat until a stop condition or an iteration cap |
| How does function calling actually work | Fresher | Fundamentals | You pass tool schemas in the request, the model returns a structured call rather than executing anything, your code runs the function and feeds the result back as a tool message. The model never touches your systems directly |
| What is ReAct and why did it matter | Fresher | Fundamentals | Interleaving reasoning traces with actions improved both accuracy and interpretability over acting alone. It is the ancestor of nearly every agent loop in use today |
| Why do agents fail more as the number of steps grows | Fresher | Reliability | Per step accuracy compounds. Ninety five percent accuracy over twenty steps is about thirty six percent end to end, which is why you shorten loops, validate at each step and add checkpoints |
| What is RAG and when do you not need it | Fresher | Retrieval | Retrieve relevant context at query time and ground the answer in it. You do not need it when the corpus fits in the context window, when the knowledge is stable enough to fine tune, or when the task is not knowledge bound |
| Explain chunking and why chunk size matters | Fresher | Retrieval | Too small loses context, too large dilutes the embedding and wastes tokens. Structure aware chunking on headings or sections usually beats fixed character splits, and overlap preserves cross boundary meaning |
| What is an embedding | Fresher | Retrieval | A dense vector where semantic similarity maps to geometric closeness. Similarity is usually cosine. Embedding model choice matters more than vector database choice for retrieval quality |
| Difference between a vector database and a normal database | Fresher | Retrieval | Vector stores index for approximate nearest neighbour search over high dimensional space using structures like HNSW, trading a little recall for large speed gains. Relational databases index for exact lookup |
| What is prompt injection | Fresher | Security | Untrusted content in the context is treated as instruction. Retrieved documents, web pages and tool outputs are all attack surfaces. There is no complete fix, so you constrain what the agent is allowed to do |
| What is MCP and what problem does it solve | Fresher | Tooling | An open protocol that standardises how agents connect to tools and data, turning an M times N integration problem into M plus N. Servers expose tools, resources and prompts over stdio or HTTP |
| What is temperature and when do you set it to zero | Fresher | Fundamentals | It scales the output distribution before sampling. Near zero for tool calling, extraction and classification where you want repeatability, higher for creative generation |
| How do you keep an agent from looping forever | Intermediate | Reliability | Hard iteration cap, wall clock timeout, token budget, repeated state detection, and a fallback that returns partial results with an explanation instead of failing silently |
| How would you evaluate an agent | Intermediate | Evaluation | Separate final task success from trajectory quality. Build a golden set from real traces, mix deterministic checks with LLM as judge, track cost and latency alongside accuracy, and run it in CI so regressions block merges |
| What is hybrid search and why does it beat pure vector search | Intermediate | Retrieval | Combine lexical BM25 with dense retrieval and fuse the rankings, usually with reciprocal rank fusion. Lexical catches exact identifiers, codes and rare terms that embeddings blur together |
| What does a reranker do | Intermediate | Retrieval | A cross encoder scores each query document pair jointly instead of comparing precomputed vectors. You retrieve fifty cheaply and rerank to five, which usually gives the single biggest quality jump in a RAG pipeline |
| How do you design agent memory | Intermediate | Memory | Split working memory in the context window, episodic memory of past runs, semantic memory of extracted facts and procedural memory of learned routines. Decide what gets written, when it is consolidated and how conflicts are resolved |
| Single agent or multi agent, how do you choose | Intermediate | Architecture | Start single. Split only when you need genuinely separate tool sets, separate context or parallelism. Every handoff loses information and multiplies token cost, so multi agent is a cost you should be able to justify |
| How do you cut agent cost in production | Intermediate | Cost | Route easy queries to a small model, cache stable prompt prefixes, trim history aggressively, use structured output instead of retries, batch offline work, and self host the high volume narrow tasks |
| What is structured output and how do you guarantee it | Intermediate | Engineering | Schema first design with Pydantic and validation on every response. Constrained decoding through a grammar or JSON schema makes malformed output impossible rather than unlikely, and beats retry loops on both cost and latency |
| Explain LoRA and QLoRA | Intermediate | Training | LoRA trains small low rank adapter matrices while the base weights stay frozen. QLoRA additionally holds the base model in 4 bit, which is what lets a 7B fine tune fit on a single consumer GPU |
| When do you fine tune instead of prompting | Intermediate | Training | When you need a consistent format or tone, when you want a small model to match a large one on a narrow task, or when the prompt has grown so long that inference cost dominates. Not for adding facts, use retrieval for that |
| How do you handle tool failures | Intermediate | Reliability | Distinguish transient from permanent. Retry with backoff on transient, feed the error text back so the model can correct its arguments, cap retries, and degrade to a clear partial answer rather than a hallucinated one |
| What do you log for an agent in production | Intermediate | Observability | Full trace with a span per step, prompt and completion, tool arguments and results, token counts and cost, latency per span, model version, and a run identifier that ties user feedback back to the exact trace |
| How do you sandbox agent generated code | Intermediate | Security | Run it in a disposable microVM or container with no host mount, no credentials, an egress allowlist, and CPU, memory and time limits. Treat all generated code as untrusted regardless of which model wrote it |
| What is excessive agency and how do you limit it | Advanced | Security | Giving an agent more permission than the task needs. Limit it with least privilege tool scopes, per user credentials instead of a shared service account, human approval on irreversible actions, and policy checks before execution |
| Design a customer support agent for ten million users | Advanced | System design | Intent router in front, small model for the easy majority, retrieval over a versioned knowledge base, tool calls scoped to the authenticated user, confidence based human handoff, full tracing, and an eval suite gating every prompt change |
| How would you debug an agent that works in dev and fails in production | Advanced | Debugging | Compare traces, not vibes. Check prompt and model version drift, retrieval quality on real queries, context window overflow, tool latency and timeouts, and the long tail of inputs your test set never contained |
| What is context engineering | Advanced | Architecture | Deliberately managing what occupies the context window at each step. Selection, compression, ordering and isolation across subagents. In 2026 it is treated as the core skill, above prompt wording |
| Explain the tradeoff between vLLM and Ollama | Advanced | Serving | Ollama optimises single user developer experience. vLLM optimises throughput under concurrency with paged attention and continuous batching. You develop on one and serve on the other |
| How do you calculate the VRAM you need | Advanced | Serving | Roughly two bytes per parameter at FP16, one byte at INT8, half a byte at 4 bit, plus KV cache that scales with batch size and sequence length, plus activation and framework overhead. Budget about twenty percent headroom |
| What is speculative decoding | Advanced | Serving | A small draft model proposes several tokens and the large model verifies them in one pass. Output is identical in distribution, but latency drops when the draft model agrees often |
| Why is prefix caching important for agents | Advanced | Serving | Agent turns share a long identical prefix of system prompt and tool definitions. Caching those keys and values avoids recomputing them each step, which is a large saving on both cost and time to first token |
| How do you version prompts and agents | Advanced | Engineering | Treat prompts as code in git with a registry, pin the model version explicitly, tie every trace to a prompt version, run the eval suite on change, and roll out behind a flag with the ability to revert instantly |
| What is GRPO and why did it become popular | Advanced | Training | Group relative policy optimisation scores a group of sampled outputs against each other rather than training a separate value model. It made reinforcement learning on reasoning and agent tasks affordable for small teams |
| How do you build a golden dataset when you have no data | Advanced | Evaluation | Start with 20 to 50 hand written cases from real user intent, generate variations synthetically, mine early production traces for failures, and grow the set every time something breaks. Every bug becomes a permanent test case |
| Explain A2A and how it differs from MCP | Advanced | Protocols | MCP connects an agent to tools and data. A2A connects independent agents to each other for discovery and task delegation. They solve different layers and are commonly used together |
| What are the failure modes of multi agent systems | Advanced | Architecture | Information loss at handoffs, agents contradicting each other, unbounded cost from chatter, no single owner of final output quality, and debugging difficulty because no one trace explains the whole run |
| How do you decide between building and buying an agent platform | Advanced | Strategy | Build when the agent logic is your product differentiator. Buy or self host open source for undifferentiated plumbing like tracing, gateways and sandboxes. Weigh data residency, cost at your volume and how fast the layer is still changing |
| What changed in agent engineering between 2024 and 2026 | Advanced | Industry | The move from prompt chaining to explicit state machines, MCP becoming the tool standard, context engineering replacing prompt engineering as the core skill, evaluation becoming a first class engineering discipline, and open weight models closing enough of the gap to make self hosting a real cost decision |
